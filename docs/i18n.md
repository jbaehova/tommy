# English and Korean text

The Mini App uses English and Korean. The HTTP request supplies its preferred language. A tag such as `ko-KR` selects Korean. An unsupported locale selects English. A missing Korean entry uses its English source.

## Mini App text

Add an English key to the relevant module under `packages/i18n/src/messages/en`. Add the same key and placeholders to its Korean module. Use the typed translator from `@tommy/i18n`. Korean sentences use 해요체. Use short nouns for buttons and labels.

The combined catalogs live in `app-catalogs.ts`. The English catalog defines the key types. `defineMessages` checks the module prefix. Plural forms come from `Intl.PluralRules`, with local rules for supported languages when necessary.

## Add a key

1. Add the key to the English module for its area. Keep the key prefix equal to the module prefix.
2. Use the literal key at its display site so the catalog checker can find it.
3. Add the Korean text to the matching module, with the same placeholder names as the English source. Keep the keys in English order.
4. Use a short verb for a Mini App button. Give the user the next available action in a status message.

For maps, store translation keys and render them at the boundary. This keeps protocol state and saved identifiers independent of the reader's language.

| Surface | API |
| --- | --- |
| Telegram messages and Mini App labels | `sourceTranslateFor(locale)` and `translateFor(locale)` |
| Local OAuth callback page | `language.translate` on the host language service |
| Server errors or status messages | `sourceText(key, params)` from `@tommy/i18n/source` |

## Text from another process

The server creates errors with `sourceText(key, params)` from `@tommy/i18n/source`. English error text can already be in a conversation, a task result or a response from a released host. Preserve the English template and placeholders when a reader depends on them. Use a new key for a change in meaning or action.

`localizeSourceText(text, locale)` finds the existing template, recovers its parameters and renders the translation. Unrecognized text passes through. The user-error formatter redacts the result before it leaves the host. Callback pages can use the language preference already stored on the server.

The English source string can travel through a released API or remain in a stored error. Its text and placeholders must keep their original meaning. `{count}` matches a number. Other placeholders can hold text. Nested reasons and details can be matched and translated separately. Keep a formerly emitted template available when its reader can still receive the old value.

Leave protocol values, database identifiers, provider instructions, log event names and user content in their original form. Translate the label that displays a value without changing its saved representation.

## Checks

Run `bun run typecheck:i18n` and `bun run i18n:check`. The catalog check reports missing translations, stale keys and ambiguous source templates. `--json` writes its findings under `.tommy-build/`. Use the Mini App tests for visible labels and escaped values.

The checker detects duplicate keys, invalid module prefixes, unknown translated keys, mismatched placeholders and ambiguous source templates. It reports untranslated keys and can reorder Korean entries with `bun run i18n:check --fix`. The JSON report is `.tommy-build/i18n-report.json`.
